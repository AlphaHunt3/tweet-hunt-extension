# XHunt UI 重设计：三套可切换的界面风格

- 日期：2026-11-14
- 状态：待审阅
- 设计稿：https://claude.ai/artifact/PBTbwA6LMGzevVWJaoSzhj （私有画布：A 柔光 / B 黑曜 / C 原生各三屏，外加动效系统）

## 1. 背景

扩展的功能没有问题，界面需要整体重做。动笔前对全部源码做了界面盘点，最影响观感和维护的问题是这些：

- **没有组件库，基础控件全靠手写。** 一个 340px 的面板里能数出约 13 种按钮、5 种标签页、4 到 7 套提示和弹层实现、5 种对话框外壳、6 种以上圆角、4 种阴影。
- **大量样式写了但不生效。** `theme-*` 是放在 Tailwind 图层之外的普通 CSS 类，于是 `hover:theme-*`、`theme-bg-tertiary/30` 这类写法不会生成任何规则。全库约 100 处，很多悬停态和底色实际不存在。
- **层级互相压。** 面板、弹层、提示分别用了 1000、9999、99999、2147483647 等 z-index，弹层会盖住触发它的元素，有时又被 X 顶栏挡住。
- **主题只分浅色和深色。** 深色固定用 X「昏暗」主题的蓝黑色，在「纯黑」主题下会出现藏青色块；不少颜色直接写死，只适配一种主题。
- **信息组织混乱。** 资料页同时存在 `标签 (值)` 和 `数字 说明` 两套写法；默认折叠成一行摘要后，删帖、改帖、讨论等入口完全看不到；悬浮面板默认位置正好盖住右栏里的 XHunt 区块。
- **状态和无障碍缺失。** 没有骨架屏，多数模块没有错误态；可点击的 div、没有名称的图标按钮、只能悬停才能看到的信息随处可见。

用户的决定：三版设计都要，并且能在扩展里切换。

## 2. 目标与非目标

**目标**

1. 用户可以在三套界面风格之间切换，切换后立即生效，不刷新页面，并在所有标签页同步。
2. 每套风格都覆盖全部界面（清单见第 6 节），浅色和深色跟随 X。
3. 现有功能、数据、接口和设置项全部保留；行为上的变化只限于第 7 节列出的条目。
4. 功能代码只写一份，三套风格只是外观和少量外壳的差异。以后新增界面，逻辑只写一次。
5. 顺带修掉第 1 节列出的系统性问题：不生效的样式、层级冲突、缺失的状态、无障碍问题。

**非目标**

- 不改后端接口、数据结构和业务规则。
- 不开放「风格」和「面板形态」的自由混搭。架构上预留拆分的余地，界面上不提供。
- 不重写与界面无关的模块：后台脚本、请求合并、缓存、信息流净化的规则引擎等。
- 不提供自定义强调色。画布里的强调色调节只是设计阶段的参数。

## 3. 用户看到的设计

### 3.1 三套风格

| | 柔光 `soft` | 黑曜 `obsidian` | 原生 `native` |
|---|---|---|---|
| 参考 | BoardUI | ObsidianUI | X 自身 |
| 气质 | 浅灰底卡片套白色内卡，亲和、清爽 | 纯黑底、半透明白层、发丝描边，高密度、专业 | 和 X 融为一体，几乎不用卡片 |
| 主题 | 跟随 X：浅色、深色 | 跟随 X：深色、浅色 | 跟随 X：浅色、昏暗、纯黑 |
| 字体 | Inter，地址和账号用 JetBrains Mono | Geist，数字用 Geist Mono | X 页面已加载的 TwitterChirp |
| 圆角（面板 / 卡片 / 控件） | 24 / 16 / 10 | 18 / 12 / 8 | 16 / 16 / 胶囊 |
| 强调色 | 靛蓝 `#5a5cf0` | 长春花紫 `#8b9cff` | X 蓝 `#1d9bf0` |
| 面板形态 | 悬浮卡片，顶部分段：关注者 / 画像 / 点评 | 左侧图标栏：概览 / 关注者 / 画像 / 点评 / 消息 / 设置；收起后只剩图标栏 | 资料页嵌入右栏，与「账户动态」合成一个模块；可改为悬浮 |
| 资料页写法 | 一张「XHunt 洞察」卡，8 格指标 | 一排数据标签，数值用等宽字体 | X 自己的「数字 + 说明」写法 |
| 动效性格 | 柔和，带一点回弹 | 快、利落 | 安静，几乎不位移 |

### 3.2 切换入口

- **设置页**：「通用」分组第一行是「界面风格」，三张带缩略预览的单选卡片，选中即生效。
- **首次引导**：在「选择感兴趣的领域」之后、「头像排名」之前新增一步「选择界面风格」，默认选中黑曜。
- **老用户升级**：默认使用黑曜。第一次打开面板时出现一次提示：「界面已更新，可以在设置里切换风格」，带「去切换」按钮，关闭后不再出现。
- **存储**：新增 `@settings/uiSkin`，取值 `soft | obsidian | native`，默认 `obsidian`。沿用现有的 Plasmo storage 钩子，跨标签页自动同步。

### 3.3 浅色和深色

- 继续沿用现有的 `@xhunt/theme`（`light | dark`）检测逻辑，现有按 `theme === 'dark'` 判断的代码不用改。
- 新增 `data-x-palette` 属性，取值 `default | dim | lights-out`，从 X 的 body 背景色推导（白、`rgb(21, 32, 43)`、黑）。原生风格用它区分昏暗和纯黑；柔光和黑曜只看浅色或深色。
- 深色下的「页面底色」统一取 X 的实际背景（现有的 `--xhunt-web-bg`），不再固定使用昏暗蓝黑，修复纯黑主题下的藏青色块。

## 4. 架构

### 4.1 分层

```
src/ui/
  tokens/        base.css：动效、间距、字号阶；skins/soft.css、obsidian.css、native.css：各风格的变量
  skin/          风格定义、useUiSkin、useXPalette、主文档属性与变量注入、字体注入、skinVariants、SkinPicker
  primitives/    对 ui-sdk 组件的薄封装：Button、IconButton、Tabs、SegmentedControl、Popover、
                 HoverCard、Tooltip、Dialog、AlertDialog、Drawer、Switch、Select、Menu、Toast、
                 Rating、Meter、Progress、Avatar、Badge、Skeleton、ScrollArea、Command 等
  shells/        面板外壳：FloatingCardShell（柔光）、RailShell（黑曜）、DockedModuleShell（原生）
src/compontents/ 功能组件在原位置改写为「数据 + 只写一次的界面」，不顺手改目录名
```

功能组件只依赖 `src/ui/primitives` 和语义变量，不直接引用 ui-sdk，也不写死颜色。

### 4.2 风格怎么生效

- **变量挂在主文档上。** 设计变量只往主文档注入一次，挂在 `<html>` 的 `data-xh-skin`、`data-xh-theme`、`data-xh-palette` 三个属性上。CSS 自定义属性会穿过 Shadow 边界向下继承（扩展现在的 `--xhunt-web-bg` 就是这么用的），所以 Plasmo 内容脚本根、`useShadowContainer` 创建的 Shadow Root、各类 portal 宿主都不需要各自处理。切换风格只改这三个属性。组件只用语义变量（第 5 节），React 代码通过 `useUiSkin()` 读取当前风格。
- **组件样式表暂不改。** 现在每个 Shadow Root 各塞一份完整的 `style.css` 文本，阶段 0 不动；阶段 5 清理时再评估是否改成共享的 Constructable Stylesheet。
- **Tailwind 改用语义名。** 配置里的颜色、圆角、阴影改为映射到 CSS 变量，例如 `bg-surface`、`text-fg-2`、`border-line`、`rounded-card`。删除写死的十六进制颜色和不生效的 `theme-*` 变体写法。
- **少量结构差异走映射表。** 三种面板外壳，加上三处写法不同的组件（资料页洞察条、右栏热门模块、面板导航），通过 `skinVariants` 按当前风格选择实现。其余组件只靠变量区分颜色、字体、圆角、阴影、密度和动效参数。
- **迁移期兼容层。** 阶段 0 里把旧的 `--bg-primary`、`--text-secondary` 等变量重新定义为新变量的别名，还没改写的旧组件也能大致跟随当前风格，不会在迁移过程中显得割裂。最后一个阶段删除这层别名。
- **字体本地打包。** Inter、JetBrains Mono、Geist、Geist Mono 都是 OFL 许可，打包进扩展，作为 `web_accessible_resources`。`@font-face` 注入到主文档（写在 Shadow Root 里的 `@font-face` 不生效），并且只注入当前风格需要的字体。不请求 Google Fonts，避免把用户 IP 暴露给第三方，与 XHunt 的隐私承诺一致。原生风格直接使用 X 页面已加载的 TwitterChirp。

### 4.3 交互基础：ui-sdk

- 键盘、焦点、选中、关闭、弹层定位和 ARIA 都交给 `@ui-sdk/react`。它不带样式，每套风格用 `data-slot` 和状态属性（`data-open`、`data-pressed`、`data-selected` 等）写各自的样式。全局样式表顶部声明 `@layer ui-sdk;`。
- **弹层原地渲染，放在浏览器顶层。** Popover、HoverCard、Tooltip、Dialog、Menu、Select 都使用浏览器的 top layer，在组件所在位置渲染，所以 Shadow Root 里的样式照常生效，层级天然在 X 页面之上。由此替换掉现有的 FloatingContainer、PortalTooltip、SimpleTooltip、HoverStatItem 弹层和各处手写的 z-index。需要渲染到别处时用 `container` 指定目标 Shadow Root。
- **现有实现 → ui-sdk 组件：**

| 现有 | ui-sdk |
|---|---|
| HoverStatItem 悬停数据卡 | hover-card |
| FloatingContainer 弹层（代币卡片、AI 分析、AI 审稿、备注、点评、打赏、社交圈） | popover |
| PortalTooltip、SimpleTooltip、CSS 悬停提示 | tooltip |
| 投票弹窗、全部投票、首次引导、AI 分身对话、幽灵关注 | dialog |
| 隐藏区域确认、清空缓存确认（现为原生 confirm） | alert-dialog |
| Tabs、TopTabNavigator、SecondaryTabs、面板分段、领域切换 | tabs、segmented-control |
| 设置开关 | switch |
| 界面风格选择、引导里的领域选择 | radio |
| 提示音效等原生 select、热门的时间和地区下拉 | select |
| 登录栏的账户菜单 | menu |
| GlobalTips 全局提示、实时通知 | toast |
| 点评星级 | rating |
| 灵魂指数、能力分、额度条、概率条 | meter、progress |
| 设置分组 | accordion |
| 黑曜面板顶部搜索 | command |
| 面板和列表滚动区 | scroll-area |

- **前置条件：React 19。** `@ui-sdk/react` 要求 `react >= 19`，扩展目前是 18.2。需要同步升级的依赖都已有兼容版本：ahooks 升到最新 3.x，recharts 升到 2.15 以上，`@plasmohq/storage` 升到 1.15，`@plasmohq/messaging` 升到 0.7.2。lucide-react 0.476 和 react-draggable 4.4.6 已兼容。Plasmo 是否需要从 0.84 升到 0.90 在阶段 0 验证。

### 4.4 动效

- **共用一套变量**（与画布一致）：主缓动 `cubic-bezier(.22, 1, .36, 1)`，回弹 `cubic-bezier(.34, 1.36, .64, 1)`；进入时同时做透明度、上移和 2px 去模糊；退出比进入快（250ms / 150ms）；标签滑块 250ms；提示框进入 150ms、退出 50ms、延迟 80ms；数字滚动 600ms，逐位错开 40ms。
- **每套风格只覆写少数变量**：柔光用回弹缓动、位移 10px；黑曜时长乘 0.8、位移 6px；原生不做模糊、位移 4px。
- 系统开启「减少动态效果」时，关闭位移和模糊，只保留透明度过渡。
- 停用现在对整个 x.com 文档调用的 View Transitions。它会影响页面本身，改为组件内的 CSS 过渡。

完整数值以画布中的 `xh-a.css`、`xh-b.css`、`xh-c.css` 为准，实现时迁移到 `src/ui/tokens/skins/*.css`。

## 7. 有意的行为变化

1. 新增「界面风格」设置和首次引导里的一步；老用户第一次打开面板时看到一次提示。
2. 原生风格下，资料页的面板内容和右栏「账户动态」合并为嵌入右栏的模块；模块头部可改为悬浮；X 隐藏右栏时（窄窗口）自动回到悬浮面板。
3. 黑曜风格下，面板收起后变成一条图标栏，替代现在 44px 的图标方块。
4. 资料页洞察默认展开（现在默认折叠成一行摘要，删帖、改帖、讨论等入口完全看不到）。仍可收起，并记住选择。
5. 柔光和黑曜的面板新增「画像」页，能力模型和灵魂指数在面板里也能看到（现在只有悬停卡片里有）。
6. 弹层改为原地渲染、放在浏览器顶层，悬停时不再淡化 X 顶栏，也不再自动把页面滚动 200px。
7. 停用对整页的 View Transitions。
8. 用应用内对话框替代原生 `confirm`（隐藏区域、清空缓存、未登录时的 AI 审稿提醒）。
9. 补齐此前缺失的状态：骨架屏、错误态和重试、空态。
10. 文案修正：隐藏区域确认按钮从「保存」改为「确认隐藏」；补齐未翻译和硬编码的字符串；中英文日期随界面语言显示。

## 10. 风险与对策

- **ui-sdk 仍是 0.1 beta，API 可能变化。** 锁定精确版本；所有调用都经过 `src/ui/primitives` 这一层薄封装，即使将来要替换，改动也局限在这一层。
- **React 19 与 Plasmo 0.84 的兼容性。** 阶段 0 第一件事就是单独验证构建和内容脚本挂载；不行就把 Plasmo 升到 0.90。
- **浏览器顶层与 X 自己的弹层叠放。** 顶层元素按打开顺序叠放，需要在真实页面上验证和 X 的菜单、图片查看器同时出现时的表现。
- **原生风格依赖 X 的 DOM 和样式**（右栏位置、TwitterChirp 字体、三种主题的色值）。沿用现有的 DOM 契约测试（`tests/e2e/dom-contract`），检测失败时回退到悬浮面板。
- **工作量大**：约 6 万行代码、100 多个组件。按阶段拆分，每个阶段都可以发布。
- **画布里的示例数据**：上线文案全部来自 `src/locales`，不使用画布中的示例账户和数字。

## 11. 已定决策

- 三套风格各自绑定自己的面板形态和资料页写法，不开放混搭；架构上预留拆分。
- 新用户和老用户默认都是黑曜。
- 底层交互用 ui-sdk，为此升级到 React 19。
- 强调色固定，不提供自定义。
- 字体本地打包，不请求远程字体。
